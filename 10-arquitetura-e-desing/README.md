# 10 - Arquitetura e Design

Estudo focado na estruturação de software, padrões de projeto, arquitetura de sistemas e boas práticas para criar bases de código escaláveis, testáveis e de fácil manutenção.

## Sumário e Roadmap

### 1. Princípios de Design
- [ ] SOLID: Single Responsibility, Open/Closed, Liskov Substitution, Interface Segregation, Dependency Inversion.
- [ ] DRY (Don't Repeat Yourself), KISS (Keep It Simple, Stupid) e YAGNI (You Aren't Gonna Need It).
- [ ] Inversão de Controle (IoC) e Injeção de Dependência (DI).

### 2. Design Patterns (Padrões GoF)
- [ ] Padrões Criacionais: Singleton, Factory Method, Abstract Factory, Builder, Prototype.
- [ ] Padrões Estruturais: Adapter, Bridge, Composite, Decorator, Facade, Proxy.
- [ ] Padrões Comportamentais: Strategy, Observer, Command, Iterator, State, Template Method.

### 3. Padrões Arquiteturais e Modelagem
- [ ] Arquitetura em Camadas (Layered Architecture) vs. Clean Architecture.
- [ ] Arquitetura Hexagonal (Ports and Adapters).
- [ ] Domain-Driven Design (DDD): Entidades, Value Objects, Agregados, Repositórios e Linguagem Ubíqua.
- [ ] Modelagem e Documentação: C4 Model, UML e formatação de diagramas arquiteturais (ex: utilizando LaTeX).

### 4. Sistemas Distribuídos e Microsserviços
- [ ] Monolitos vs. Microsserviços: Vantagens e desvantagens.
- [ ] Padrões de Microsserviços: API Gateway, Circuit Breaker, Saga Pattern, Event Sourcing e CQRS.
- [ ] Descoberta de Serviços (Service Discovery) e Balanceamento de Carga (Load Balancing).

## Referências Úteis
* Livro: Clean Architecture (Robert C. Martin - Uncle Bob).
* Livro: Designing Data-Intensive Applications (Martin Kleppmann).
* Livro: Domain-Driven Design: Tackling Complexity in the Heart of Software (Eric Evans).
